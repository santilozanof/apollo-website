# Apollo Chat 3.0 post-deployment repair candidate — 2026-10-27

The reported production replies were inspected read-only at release `dd3535d2da87ca5a76d3c454c6f0003b2ee996f3`. This document records a local candidate, not a production acceptance result.

The Spotify reply had a successful playback read but no listening-history read. Chat's `spotify_read` tool exposed only current playback even though Music Insights already had stored plays and aggregation APIs. The candidate adds a read-only `spotify_history_read` adapter over those existing APIs, including period/custom-range ranking, play counts, known duration and coverage. Explicit personal listening-history questions call it before answer generation. The planner's source description now names this capability.

The Calendar/Canvas/WHOOP question was incorrectly classified as public Google research because the personal-data guard did not recognize “my Google Calendar.” The candidate sends explicit multi-source personal requests to the authenticated Calendar, Tasks/Canvas and WHOOP adapters. Calendar evidence now retains events when a different source fails and reports source-specific errors and connection states. It never substitutes a public Google sign-in page for account data.

The ordinary long-form story request used “entire story,” which was missing from the story visual and research triggers. The candidate includes that generic wording and tests verified image/entity insertion in a streamed, persisted response. Media must still resolve from a verified source; no asset is invented. Actual live-model output and provider-backed entity click behavior require staging or production acceptance for this revision.

The analog/digital answer already contained a valid Markdown table. A schema-only comparison check requested a recovery block anyway, producing an unrelated Option 1/Option 2 table. The candidate accepts complete Markdown tables and rejects generic placeholder table rows. It adds a bounded declarative diagram component and responsive table/diagram styling. A localhost browser fixture was inspected at desktop and 390 px: the desktop table used available width, the mobile three-column table scrolled within its own container, and the diagram stacked without document-level overflow.

The espresso-machine discussion was in the same saved chat as the reported summary request. A regression test verifies that normal current-thread context does not merge another chat. No memory architecture change was made.
